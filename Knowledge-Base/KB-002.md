# KB-002: Azure Virtual Machine Low Disk Space Troubleshooting

## Overview

This knowledge base article provides a structured troubleshooting approach for Azure Virtual Machines that are running low on disk space and experiencing application or performance issues.

---
![Azure VM Monitoring and Storage Architecture](../Images/azure-vm-monitoring-storage-architecture.png)


## Common Symptoms

A user may experience one or more of the following symptoms:

- VM performance becomes slow.
- Applications running on the VM start failing.
- Files cannot be created or saved.
- Application logs cannot be written.
- Disk usage reaches a very high percentage.
- The operating system reports low disk space.

---

## Troubleshooting Checklist

### 1. Check Virtual Machine Status

Verify that the Azure Virtual Machine is in the **Running** state.

If the VM is stopped or deallocated, start the VM and check the issue again.

---

### 2. Check Disk Usage

Connect to the Virtual Machine and check the available disk space.

Identify which disk or partition is running low on space.

For Windows VMs, check the available space on the OS drive.

For Linux VMs, review the filesystem usage.

---

### 3. Identify Large or Unnecessary Files

Check for files that may be consuming excessive disk space.

Common examples include:

- Old application logs
- Temporary files
- Downloaded files
- Crash dumps
- Unnecessary application data

Remove files only after confirming that they are safe to delete.

---

### 4. Review Application Logs

Check whether the application is generating unusually large log files.

If required, review the application's logging and retention configuration to prevent logs from continuously consuming disk space.

---

### 5. Check Azure Disk Configuration

Review the managed disk attached to the VM.

Check:

- OS disk
- Data disks
- Disk size
- Disk type
- Available capacity

If the existing disk does not provide enough capacity, consider increasing the disk size.

---

### 6. Review Monitoring

If Azure Monitor is configured, review disk-related metrics and alerts.

A low disk space alert can help identify the issue before the disk becomes completely full.

---

## Root Cause Examples

Common causes of low disk space on Azure Virtual Machines include:

- Excessive application logs.
- Temporary files accumulating over time.
- Large application data files.
- Crash dumps or diagnostic files.
- Insufficient disk capacity.
- Lack of regular disk cleanup.

---

## Resolution Approach

Follow these steps in order:

1. Verify the VM status.
2. Check disk and partition usage.
3. Identify large files or directories.
4. Remove unnecessary files safely.
5. Review application log retention.
6. Check the managed disk size.
7. Increase disk capacity if required.
8. Test the application again.
9. Monitor disk usage after the change.
10. Document the root cause and resolution.

---

## Security and Maintenance Best Practices

- Do not delete system or application files without verifying their purpose.
- Configure appropriate log retention.
- Monitor disk usage regularly.
- Configure alerts for low disk space.
- Keep sufficient free space available for normal application operation.
- Increase disk capacity when cleanup alone is not sufficient.

---

## Verification

After applying a cleanup or disk configuration change:

- Confirm that sufficient disk space is available.
- Verify that the affected application is running normally.
- Check that new files and logs can be created.
- Monitor disk usage for further increases.
- Confirm that the customer can use the affected application normally.

---

## Conclusion

Azure VM disk space issues should be investigated by first identifying which disk or partition is affected and what is consuming the available capacity.

Checking disk usage, application logs, unnecessary files, and managed disk configuration helps identify the root cause without making unnecessary changes to the VM.
