# KB-005: Azure Load Balancer and Application Gateway Health Probe Troubleshooting

## Overview

This article provides a practical checklist for investigating situations where an Azure Load Balancer or Application Gateway cannot send traffic to a backend server because the backend is marked unhealthy.

## Common Symptoms

- Application is unreachable through the Load Balancer or Application Gateway.
- Backend VM is running but shown as unhealthy.
- Users receive 502 Bad Gateway errors.
- Health probe shows failed or unavailable status.

## Troubleshooting Checklist

### 1. Check Backend VM Status

Confirm that the backend VM is running and that the application service is available.

### 2. Verify the Backend Port

Check which port the application is actually listening on and compare it with the port configured in the health probe.

### 3. Check Health Probe Configuration

Review the probe protocol, port, and health check path where applicable.

### 4. Check Network Security Rules

Verify that the required probe and application traffic is allowed by the Network Security Group and operating system firewall.

### 5. Test the Application Directly

Test the application from inside the VM or through its internal address to confirm that the service itself is responding.

### 6. Check Backend Health

After making any required changes, review the backend health status and confirm that the server is marked healthy.

## Root Cause Examples

Common causes include:

- Incorrect health probe port.
- Incorrect health probe path.
- Application service not running.
- NSG or firewall blocking required traffic.
- Backend server not responding to the configured probe.

## Resolution Approach

Start by checking the backend server and application, then compare the health probe configuration with the actual application settings. Correct the mismatch, verify network access, and confirm the backend becomes healthy.

## Best Practices

- Keep health probe settings aligned with the application configuration.
- Monitor backend health regularly.
- Avoid opening unnecessary network ports.
- Use a dedicated health endpoint when the application supports one.
- Review probe configuration after application or port changes.

## Verification

Confirm that the backend server is marked healthy and test the application through the Load Balancer or Application Gateway.

## Conclusion

Backend health is one of the first things to check when traffic is not reaching an application through an Azure Load Balancer or Application Gateway. Comparing the probe configuration with the actual application response usually helps narrow down the issue quickly.
